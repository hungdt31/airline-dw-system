\section{Thiết kế hệ thống}

\subsection{Kiến trúc tổng thể}

Hệ thống được thiết kế theo kiến trúc phân tầng (Layer Architecture) gồm 5 tầng,
mỗi tầng có trách nhiệm rõ ràng và giao tiếp với tầng liền kề:

\begin{enumerate}
    \item \textbf{Tầng Nguồn (Sources Layer):}
          Dữ liệu thô từ 3 file CSV của Kaggle:
          \texttt{flights.csv} (5,8M dòng, 31 cột),
          \texttt{airlines.csv} (14 hãng),
          \texttt{airports.csv} (322 sân bay).

    \item \textbf{Tầng ETL (Extract--Transform--Load Layer):}
          Module \texttt{etl/} gồm 3 file: \texttt{extract.py}, \texttt{transform.py}, \texttt{load.py}.
          Được điều phối bởi \texttt{pipeline.py} theo kiến trúc streaming 4 bước.

    \item \textbf{Tầng Data Warehouse (DW Layer):}
          Cơ sở dữ liệu SQLite (\texttt{warehouse/airline\_dw.db}) lưu trữ dữ liệu theo Star Schema
          với 1 fact table, 5 dimension tables và 6 index OLAP.

    \item \textbf{Tầng Phân tích (Analytics Layer):}
          File \texttt{queries/olap\_queries.sql} chứa 9 nhóm truy vấn OLAP.
          Dashboard \texttt{dashboard/app.py} cung cấp giao diện tương tác 2 tab
          được xây dựng bằng Streamlit + Plotly.

    \item \textbf{Tầng Khai phá (Mining Layer):}
          Module \texttt{mining/} thực hiện feature engineering, huấn luyện và đánh giá
          5 thuật toán Machine Learning, xuất báo cáo HTML so sánh.
\end{enumerate}

\subsection{Pipeline ETL}

Pipeline được tổ chức thành 4 bước tuần tự trong \texttt{pipeline.py}:

\subsubsection{Bước 1 -- Đọc và transform dimension nhỏ}

File \texttt{airlines.csv} và \texttt{airports.csv} được đọc toàn bộ vào RAM (dữ liệu nhỏ)
và transform thành \texttt{dim\_airline}, \texttt{dim\_airport} qua \texttt{transform.py}.
Đồng thời, file \texttt{flights.csv} được \textit{quét một lần} với chunk lớn (300.000 dòng)
chỉ để thu thập các ngày duy nhất (\texttt{scan\_dim\_date}) rồi xây dựng \texttt{dim\_date}
hoàn chỉnh (ngày, tháng, quý, tuần, thứ, cuối tuần) bằng \texttt{pd.to\_datetime} vectorized.

\subsubsection{Bước 2 -- Khởi tạo schema}

Schema được tạo từ file SQL (\texttt{warehouse/schema.sql}) thông qua \texttt{conn.executescript()}.
Cấu hình SQLite để tối ưu hiệu suất ghi:
\begin{lstlisting}[language=SQL, caption={SQLite PRAGMA tối ưu ghi}]
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
\end{lstlisting}
Chế độ WAL (Write-Ahead Logging) cho phép đọc không chặn ghi và tăng throughput INSERT.

\subsubsection{Bước 3 -- Nạp dimension tables và lấy lookup maps}

Sau khi 5 dimension table được nạp vào DB, pipeline truy vấn lại để xây dựng
lookup dictionary \textit{(surrogate key mapping)}: \texttt{airline\_map},
\texttt{airport\_map}, \texttt{date\_map}, \texttt{delay\_reason\_map}.
Các map này được dùng trong bước 4 để map chuỗi (IATA code, ngày) sang integer surrogate key
bằng \texttt{pandas.Series.map()} --- vectorized, không dùng loop.

\subsubsection{Bước 4 -- Streaming fact\_flights}

Đây là bước tốn thời gian nhất, xử lý 5,8M dòng theo chu trình:
\textit{đọc chunk → transform → INSERT batch → giải phóng RAM → chunk tiếp theo}.

\begin{lstlisting}[language=Python, caption={Vòng lặp streaming trong pipeline.py}]
CHUNK_SIZE   = 100_000   # row/chunk ~ 120 MB RAM
INSERT_BATCH = 50_000    # row/INSERT into SQLite

for chunk in stream_flights(chunksize=CHUNK_SIZE):
    fact = transform_chunk(chunk, airline_map, airport_map,
                           date_map, delay_reason_map)
    del chunk                              # release RAM immediately
    load_fact_flights(conn, fact, chunksize=INSERT_BATCH)
    del fact
\end{lstlisting}

\textbf{Tối ưu dtype trong extract.py:}
Thay vì dùng dtype mặc định của pandas (float64/int64), file \texttt{extract.py}
khai báo tường minh các dtype nhỏ hơn cho mỗi cột:
\begin{lstlisting}[language=Python, caption={Tối ưu dtype tiết kiệm ~60\% RAM/chunk}]
FLIGHTS_DTYPE = {
    "YEAR":           "int16",   # replace int64
    "MONTH":          "int8",
    "DAY":            "int8",
    "DEPARTURE_DELAY": "float32", # replace float64
    "ARRIVAL_DELAY":  "float32",
    # ... all delay columns are float32
}
\end{lstlisting}
Nhờ đó mỗi chunk 100.000 dòng chỉ chiếm khoảng \textbf{120 MB RAM}
thay vì \textasciitilde{}300 MB nếu dùng dtype mặc định.

\textbf{Vectorized transform với \texttt{numpy.select()}:}
Logic phân loại nguyên nhân delay được thực hiện hoàn toàn vectorized
thay vì dùng \texttt{apply()} row-by-row (chậm hơn 50--100 lần):
\begin{lstlisting}[language=Python, caption={np.select() phân loại nguyên nhân delay}]
conditions = [
    df["WEATHER_DELAY"]       > 0,
    df["AIR_SYSTEM_DELAY"]    > 0,
    df["LATE_AIRCRAFT_DELAY"] > 0,
    df["AIRLINE_DELAY"]       > 0,
    df["SECURITY_DELAY"]      > 0,
]
df["delay_reason_key"] = np.select(
    conditions, choices, default=delay_reason_map["NO_DELAY"]
)
\end{lstlisting}

\subsubsection{Chiến lược xử lý missing values}

\begin{itemize}
    \item Tất cả cột delay (\texttt{ARRIVAL\_DELAY}, \texttt{WEATHER\_DELAY}, v.v.) được
          điền \texttt{fillna(0.0)} --- NaN có nghĩa ``không có delay loại này''.
    \item Các bản ghi thiếu \texttt{AIRLINE}, \texttt{ORIGIN\_AIRPORT} hoặc
          \texttt{DESTINATION\_AIRPORT} bị loại trong \texttt{extract.py} trước khi transform.
    \item Bản ghi không map được foreign key (airline/airport không trong dimension table)
          bị loại qua \texttt{dropna(subset=[...])} trong \texttt{transform\_chunk()}.
\end{itemize}

\subsubsection{Indexes OLAP}

6 index được tạo trên \texttt{fact\_flights} để tăng tốc các OLAP query thường gặp:
\begin{lstlisting}[language=SQL, caption={Indexes tăng tốc OLAP}]

CREATE INDEX idx_fact_origin    ON fact_flights(origin_airport_key);

\end{lstlisting}

\subsubsection{Lý do chọn Star Schema thay vì Snowflake}

\begin{enumerate}
    \item \textbf{Hiệu suất truy vấn cao hơn:} SQLite không có cost-based query optimizer phức tạp.
          JOIN trực tiếp từ fact sang dimension (1 bước) nhanh hơn JOIN nhiều cấp trong Snowflake.
    \item \textbf{Đơn giản hóa OLAP query:} Tất cả 9 nhóm query trong \texttt{olap\_queries.sql}
          chỉ cần 1--2 JOIN, không cần JOIN chuỗi 3--4 bảng.
    \item \textbf{Phù hợp với quy mô dữ liệu chiều:}
          Dimension lớn nhất (\texttt{dim\_airport}) chỉ có 322 bản ghi,
          dư thừa dữ liệu là không đáng kể.
\end{enumerate}

\subsection{OLAP Queries}

File \texttt{queries/olap\_queries.sql} chứa 9 nhóm truy vấn phân tích đa chiều:

\begin{enumerate}
    \item \textbf{Tổng số chuyến bay theo tháng/quý/năm} (Roll-up): tỷ lệ delay, tỷ lệ hủy chuyến
          theo từng đơn vị thời gian.
    \item \textbf{Top 5 hãng hàng không có nhiều chuyến bay nhất}: tổng chuyến,
          số chuyến hủy, tỷ lệ hủy.
    \item \textbf{Tỷ lệ đúng giờ OTP theo hãng} (On-Time Performance):
          $\text{OTP} = 1 - \frac{\text{delayed}_{15}}{\text{total}}$,
          delay trung bình theo từng hãng.
    \item \textbf{Tỷ lệ hủy chuyến theo nguyên nhân}: mã A (Carrier), B (Weather),
          C (NAS), D (Security) với tỷ lệ phần trăm dùng \texttt{SUM() OVER()}.
    \item \textbf{Delay trung bình theo sân bay đi và sân bay đến}:
          Top 10 sân bay có \texttt{avg\_departure\_delay} và \texttt{avg\_arrival\_delay} cao nhất
          (lọc $> 100$ chuyến).
    \item \textbf{Nguyên nhân delay và thời gian delay trung bình}:
          JOIN \texttt{dim\_delay\_reason}, GROUP BY theo loại nguyên nhân.
    \item \textbf{Xu hướng delay theo tháng/mùa}: phân loại mùa Đông/Xuân/Hè/Thu
          bằng \texttt{CASE WHEN}.
    \item \textbf{Delay theo khung giờ bay}: phân chia 4 slot
          (00--06 đêm khuya, 06--12 sáng, 12--18 chiều, 18--24 tối)
          từ cột \texttt{scheduled\_departure} (định dạng HHMM).
    \item \textbf{Top 5 sân bay có tỷ lệ gián đoạn cao nhất}:
          $\text{disruption\_rate} = \frac{\text{cancelled} + \text{delayed}_{15}}{\text{total}}$
          (lọc $> 1.000$ chuyến).
\end{enumerate}

\subsubsection{Thiết kế bộ lọc động trên Sidebar}

Sidebar có 4 nhóm bộ lọc kết hợp với nhau qua hàm \texttt{W()} tạo mệnh đề \texttt{WHERE} động:

\begin{itemize}
    \item \textbf{Thời gian:} Radio chọn chế độ ``Tháng'' hoặc ``Quý'',
          sau đó multiselect tháng (1--12) hoặc quý (Q1--Q4).
    \item \textbf{Hãng hàng không:} Multiselect theo tên đầy đủ,
          lookup từ \texttt{dim\_airline}.
    \item \textbf{Sân bay đi:} Chọn bang (50 bang + territory) $\rightarrow$
          sau đó chọn sân bay cụ thể. Khi đổi bang, danh sách sân bay reset tự động
          qua \texttt{st.session\_state}.
    \item \textbf{Sân bay đến:} Tương tự cấu trúc sân bay đi.
\end{itemize}

Tất cả query được cache bằng \texttt{@st.cache\_data(ttl=300)} để tránh re-query
khi người dùng tương tác mà không thay đổi bộ lọc.

\subsubsection{Kiến trúc từng thuật toán}

\begin{itemize}
    \item \textbf{Logistic Regression:} solver=\texttt{lbfgs}, C=1.0, max\_iter=1000,
          class\_weight=\texttt{'balanced'}.
    \item \textbf{Random Forest:} 100 estimators, max\_depth=10, min\_samples\_leaf=50,
          class\_weight=\texttt{'balanced'}, n\_jobs=-1.
    \item \textbf{Neural Network (MLP):} Kiến trúc [10 $\to$ 64 $\to$ 32 $\to$ 1],
          ReLU + Dropout(0.3), Adam optimizer lr=0.001, batch\_size=2048, epochs=20.
    \item \textbf{XGBoost:} n\_estimators=300, max\_depth=6, learning\_rate=0.1,
          scale\_pos\_weight=3.76 ($= \frac{|\text{negative}|}{|\text{positive}|}$).
    \item \textbf{LightGBM:} n\_estimators=300, num\_leaves=63, learning\_rate=0.1,
          is\_unbalance=True.
\end{itemize}

\subsubsection{Chiến lược xử lý mất cân bằng lớp}

Phân phối nhãn: khoảng 79\% không delay (lớp 0), 21\% delay (lớp 1).
Chiến lược: sử dụng trọng số lớp thay vì oversampling/undersampling vật lý
để tránh tăng kích thước dữ liệu và thời gian huấn luyện:
\begin{itemize}
    \item \texttt{class\_weight='balanced'} (sklearn): tự động đặt trọng số tỷ lệ nghịch
          tần suất lớp --- lớp minority (delay) được tăng ảnh hưởng lên $\approx 3{,}76\times$.
    \item \texttt{scale\_pos\_weight=3.76} (XGBoost): tương đương.
    \item \texttt{is\_unbalance=True} (LightGBM): tự động xử lý.
\end{itemize}
Đánh giá bằng AUC-ROC và F1 thay vì Accuracy để tránh misleading
khi lớp minority chiếm tỷ lệ nhỏ.
